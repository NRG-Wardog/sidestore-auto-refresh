# Generated OpenSSL 3.5.9 LTS host experiment

This is a separate generated dependency experiment, **not** an edit of either
existing framework, gitlink, application project or product pin. OpenSSL 3.5 LTS
is supported until 2030-04-08; 3.6 reaches end-of-support on 2026-11-01. Sources:
[official roadmap](https://openssl-library.org/roadmap/) and
[official downloads](https://openssl-library.org/source/), checked 2026-10-25.

`source.json` pins the official 3.5.9 source archive and independently fetched
published checksum:
`603f5602e2eef00d77fbd429d34dcd5822bb301757a1bc9cdb24c670f1eb859a`.
The downloaded archive was checked locally before inspection; all entries are
regular files/directories. No code from the source archive was executed locally.

## Recipe

`build.py` permits native macOS only, using Xcode 26.4.1 and its native arm64 or
x86_64 target. It uses the official OpenSSL Configure/build files directly, not
the Apple wrapper's signing-identity-discovery Makefile. Explicit flags are
`no-shared no-module enable-legacy no-asm`. The pinned upstream
`providers/build.info` makes legacy part of libcrypto when `module` is disabled;
default is built in independently. Runtime probes must still prove activation
and bind the actual default/legacy dispatch images.

The recipe sanitizes inherited compiler, Perl, Make, loader and module-search
variables, chooses Apple compiler/archive tools explicitly, verifies source
checksum before safe extraction, and checks that archived source bytes did not
change. It records compiler/tool hashes, source inventory, SDK, architecture,
minimum OS, provider/configuration data, static archive hashes, generated library
and header inventories, and matching binary/dSYM UUIDs. SOURCE_DATE_EPOCH and
ZERO_AR_DATE are fixed; bit-for-bit repeatability is not yet claimed.

The generated output is a dedicated
`lts-build/generated/OpenSSL.framework/Versions/A/OpenSSL`. There is no overwrite
of the shipped/pinned framework directories. The build creates no signing
identity lookup, keychain change, user certificate or product release. It builds
libraries only, not either application. Source-package tests are not claimed run.

```sh
python3 -B ci/issue53-lts/test_recipe.py
python3 -B ci/issue53-lts/build.py --output /new/absolute/lts-build
```

## Qualification boundary

The separate read-only `issue53-lts-source.yml` workflow first builds the source
recipe, then uses the established crypto, actual maintained ZSign consumer and
cold-process coexistence probes. Only the **host test role** receives generated
LTS; the embedded comparison remains the exact current 3.6.2 archive. The explicit
input-variant receipt binds the generated binary back to the official source,
recipe and build receipt. Both pre-test and post-test generated bytes are checked.
No old pin is relabeled as LTS and no production dependency is silently replaced.

The gate must prove provider activation, malformed/truncated PKCS#12 rejection,
PEM/DER roundtrips, independent signature verification, actual CodeDirectory/CMS
attributes and page hashes, deliberately untrusted synthetic chain handling, and
both cold-process load orders. Failure quarantines the candidate. Evidence uploads
contain receipts/logs only, not synthetic keys, framework outputs or source trees.

Even a passing macOS experiment does **not** provide an iOS artifact or approve
application integration. The next phase must explicitly build/qualify the needed
iOS/simulator slices and define the generated dependency's Xcode and packaging
provenance boundary. No device execution, Apple-trusted signing or production
admission is claimed by these receipts.

## Explicit iOS consumer generation

After the source-equivalent macOS qualification gate, run on macOS/Xcode 26.4.1:

```sh
python3 -B ci/issue53-lts/build_ios.py --output lts-ios-build
python3 -B ci/issue53-lts/install_ios.py --built lts-ios-build --consumer path/to/LiveContainer
```

The installer requires the reviewed PBX file reference to the dedicated generated
path, refuses existing output and verifies complete output inventory plus source
and both recipe hashes. It never writes inside the historical `OpenSSL` gitlink.
Use the generated receipt and `GeneratedDependencies/OpenSSL35/provenance.json`
in the candidate compiler-input and final package identity manifests. The receipt
covers both device/simulator slices and dSYMs; signing/post-link changes require
the existing final executable/UUID identity comparison, not a pre-sign whole-file
hash alone. Preserve `build-ios.log` and each slice's `configdata.txt` even on
failure. All three thin and both merged simulator architecture probes compile
and link real public modules without executing an iOS binary on macOS.

This host migration does not imply embedded SideStore's separate 3.6.2 library
was upgraded. Its explicit package-owner adapter and actual consumer validation
remain a separate migration, never deduplication by install-name accident.
