All 13 attachments are bound to the exact method/device and raw XCTest export. Exact native case counts are 1 pass/0 failures/0 skips for each arm. Full actual compiled scalar/simple-plural/compound resource checks remain mandatory.

Missing, duplicate, misassociated, nonfinite, stale or malformed evidence fails. A/B inside-Form and C/D outside-Form geometry is recorded even when wrong, allowing the expected control defect to remain visible. Independent raster review is mandatory. The CI result can only be collection-complete; it never certifies visual or product correctness. The review decision is:
- Control does not reproduce: inconclusive.
- Candidate has mirrored glyphs, wrong Hebrew layout/chrome or wrong geometry: rejected.

The first run does not exercise fake pending writes, scrolling/recycling, repeated cycles, cold Hebrew, Chinese, relaunch or full application state. Those remain required before accepting a product correction. No passing outside witness can excuse failing Form pixels.

## Budgets and retention

One build-for-testing command and two separate test-without-building commands. Each subprocess is capped at 240 seconds and consumes a shared 18-minute experiment deadline; each XCTest method has a distinct 150-second allowance inside that cap. Setup/boot also consume the shared deadline. Finalization has at most 6 additional minutes and the job reserves upload time within 35 minutes. No timeout is expanded after failure.

Synchronous command ownership retains the actual unreaped child identity before any TERM/KILL, then permanently switches to read-only group-disappearance checks after reaping. Popen creation itself is not interruptible; elapsed spawn time is deducted before waiting and its return does not prove target-exec readiness. Primary timeout and cleanup errors are separate; unsettled writers block the next arm and stable archive claims. Source/project/xctestrun bytes are checked before/after.

Failure-first logs, raw xcresults, generated sources, visible workflow.yml, source/builder seals and compiled products are retained. Archives preserve exact paths/types/full modes/symlink targets/bytes and verify before/after inventories plus readback. Retention is bounded to 25,000 entries, 2 GiB total and 1 GiB per file with shared finalization-deadline checks per chunk. Incomplete retention fails; no missing or unstable archive is promoted to valid evidence. Mutable evidence is outside the upload path. Only after owned writers and the owned simulator settle is it indexed, archived, read back and atomically moved into the publish directory. Otherwise that directory receives only a bounded parent-written failure receipt retaining the primary outcome and bounded in-memory failed-command identity/phase, timeout and owned-group settlement metadata. No mutable-file reads supply that fallback receipt. The workflow uploads only this publish directory and the portable test log. The evidence index excludes only itself. Dot-directory workflow bytes are copied to visible workflow.yml so upload-artifact retains the indexed file.

Portable checks: P2_FORM_SOURCE=/absolute/verified/source python3 -B -m unittest discover -s ci/p2/form_direction -p 'test_*.py' -v. Native behavior is unproved until the actual artifact is independently reviewed.
