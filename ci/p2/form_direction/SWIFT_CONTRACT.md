# Bounded paired Form-direction fixture

Owned templates: `App.swift.in` and `FormDirectionTests.swift.in`.

Generator dependencies: concatenate the same exact production localization, language-section, UIKit alert, SceneDelegate and View.textFieldAlert declarations used by the authenticated settings generator. This template needs no clipboard helper. The runner needs the independently generated `ExpectedStrings` and XCTest/UIKit. The Xcode test file/class is FormDirectionTests, with exactly testControlRoundTrip and testCandidateRoundTrip. The app executable/bundle can remain the fixture's P2SettingsHost, provided its domain is isolated from LiveContainer.

One immutable --form-arm value is required per process. Both branches call the same formContent declaration. Control has Form { formContent }; candidate adds the Group with current inherited direction and a fixed LTR environment on Form. The container probe sits inside the Form override. No live branch swap, .id reset, transform or semantic override exists. The product branch and frozen experimental candidate are not edited.

Before constructing any view, each fixture process resets only its isolated V3AppLanguage preference to English. This is logged as bootstrapScope=fixture-domain-before-view-construction, bootstrapLanguage=en and bootstrapPriorLanguage. The measured EN→HE→EN changes happen only through the exact production Picker.

Original reproduction structure retained: NavigationView/Form, production language section, fixture message, text field, A/B row and three fixture action buttons. Explicit shared additions: zero-size passive environment probes, an automatic synthetic Picker, and a synthetic NavigationLink. The fixture state header uses an explicit header closure so it can carry a probe. The old clipboard observer/receipt is omitted. Telemetry remains outside Form. These are instrumented component fixtures, not unchanged full-host rendering or auth/guest-lifetime proof. Control must independently reproduce the raster symptom before a candidate improvement is meaningful.

JSON attachment `<arm>-form-direction.json`, schema `p2-form-direction-v1`:
- arm: control/candidate; method: exact XCTest method; completed: Bool; failures: strings
- observations: six ordered stages en-initial-immediate, en-initial-later, he-selected-immediate, he-selected-later, en-return-immediate, en-return-later
- Each observation: stage, language, stateBefore, stateAfter, captureStartedUptime, pngFinishedUptime, captureFinishedUptime, png, ax, geometry
- PNG/text names exactly `<arm>-<stage>.png` and `.txt`. Each must associate with this exact test case in xcresult, and have unique nonempty exported bytes. No attachment filename is an assumed path or trusted association by itself.
- stateBefore/stateAfter must match exactly within each observation. Later capture begins at least 0.8 seconds after the immediate capture finishes. Times are actual runner monotonic uptime, not claimed zero-latency screenshots. Each selection records pickerTapStartedUptime, tapStartedUptime, tapFinishedUptime, readyUptime; readiness requires all environment observations to settle. Preserve actual delays for visual interpretation.
- transitions: exactly en→he, he→en, with before/after states, actual Picker and option tap label/identifier/hittable/frame/role receipts, and the times above. pickerCandidates is exactly the unique live Picker receipt. buttonCandidates and textCandidates are bounded actionable exact-label inventories, each with at most one result. A sole result uses optionContainment=single-actionable-target and empty buttonTextDescendants. When both roles have one result, the fixture queries the unique button's exact-label actionable static-text descendants and requires exactly one whose complete receipt equals the unique global text; optionContainment=unique-button-contains-unique-text and buttonTextDescendants preserves that proof. An unrelated button/text pair is rejected. optionRole records the button when this explicit containment proof exists, otherwise the sole actionable role. The selected inventory must equal optionTap.
- finalState must match last observation state; visualVerdict must remain not-evaluated-requires-independent-raster-review.

App state schema `p2-form-direction-state-v1` includes arm, processToken/sessionToken UUIDs, processIdentifier, processArguments, languageEnvironment, bootstrap fields, language/hostDefaultLanguage, locale, direction, text, originalMessage, zero action counters/witnessChoice, and probes.

Exactly six probes: inherited, container, productionSectionBoundary, header, picker, content. Each reports locale/direction, stable coordinator UUID identity, app-process monotonic observation uptime, and positive revision incremented only when its observed identity/locale/direction changes. Every probe's uptime and revision must advance across both transitions, including candidate container because locale changes. App-process timestamps are compared only with prior app-process readings, never runner timestamps. Probe identity must persist through all six stages and both transitions. Process/session/PID must also persist within one arm and differ between the two arm launches. Every locale is the current language. Every direction is the selected direction except candidate container is always ltr. These are real @Environment reads at the instrumented locations, not computed expectations. ProductionSectionBoundary is NOT the internal production header or Picker environment. The header and picker probes observe explicitly synthetic fixture elements. Never relabel this distinction.

Geometry captures viewport, nine named elements, all exact localized production Language header AX matches, and every exposed descendant of the synthetic native NavigationLink. A chevron might not be separately exposed by AX; its actual raster remains mandatory for visual review. Do not synthesize a chevron rectangle. Bounds must be finite, nonempty and intersect the viewport. Actual A/B and C/D order is recorded in contentOrderCorrect and outsideOrderCorrect, not used to abort collection. Candidate geometry acceptance requires LTR English and RTL Hebrew; control defects remain collected. This does not prove glyph raster orientation.

Any missing/malformed state, environment, identity, required geometry or timing gate throws and emits completed=false plus partial screenshots/AX. Parser must additionally reject absent/duplicate/misassociated mandatory artifacts even if XCTest itself passed. No visual or full P2 success is asserted automatically.

Python API: verify_arm(directory, arm, valid_png) reads raw manifest.json and resolves the exact associated report internally. valid_png receives a pathlib.Path and must return the Boolean True. verify_pair(control_result, candidate_result) requires separate process/session/PID and the same manifest device ID; the runner separately authenticates identical runtime/toolchain. visual_verdict(pair, review=None) remains pending without independent raster review and can at most report bounded-fixture-improvement-only, never product acceptance.

## Failed-run diagnostic continuation

A cross-transition coordinator identity change remains a native XCTest failure and permanently latches diagnosticOnly. The launch baseline is never rebased. The first changed identity for each of the six named probes is retained (at most six rows). Only this identity failure permits continuation of the already bounded HE/EN Picker route. All other state, environment, process, session, timing and whole-state before/after capture checks remain throwing gates. Subsequent captures and transitions are written to diagnosticObservations/diagnosticTransitions, never to accepted observations/transitions. A latched run cannot report completed=true and the verifier independently rejects diagnosticOnly even if a report forges completed=true and empty failures. Diagnostic pixels may inform a future hypothesis; they cannot certify lifecycle preservation or product acceptance.

This change does not claim that coordinator lifetime equals user-state lifetime. A later reviewed acceptance change would require nondefault live text/selection preservation and bounded make/update/dismantle evidence to distinguish multiple Section background instances from recreated instances. This diagnostic continuation deliberately does not add those mechanisms or change the production arms.
