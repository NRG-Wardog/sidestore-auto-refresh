# Defensive ELF metadata bounds admission

This additive source basis is `p0-elf-metadata-bounds-v1`.
It does not modify or satisfy the historical native/constructor admission gates.
Its exact review anchor binds the independently reviewed two-phase native
evidence and the actual published lock-only descendants. Build eligibility is
limited to the ordinary gated release workflow; it is not an IPA or login claim.

Fresh coverage is retained from the isolated two-phase validation workflow:
- Exact reviewed production metadata repair and its separately reviewed host-test
  fixture successor, with actual immutable commit/tree/blob identities.
- 713 actual production-helper checks in each normal, optimized and ASan+UBSan
  variant, zero failures/skips, retained commands/stdout/stderr and source hashes.
- Eight ordinary host-double native boundaries, five SideSign native package
  tests, the exact 42 service/host consumer tests, real dependency resolution and
  unsigned iPhoneOS compilation of SideStore and LiveContainer.
- Real resolver bytes and final published lock-only descendants. The seven-owner
  graph and all recursive children must agree across capture, publication and IPA
  packaging. LiveContainer and transport runtime owners stay unchanged.
- Quiescent owned command writers and an exact retained evidence index.

Historical native83 and constructor2105 artifacts are authenticated against the
immutable previous review and retained as historical-only references. Complete
unchanged constructor-dispatch, procedure, import-router definitions and TLS /
diagnostic headers are compared byte-for-byte. The complete loader changed, so
this comparison never constitutes a fresh guest execution result.

Guest execution, proprietary-input execution, ADI execution, physical-device
validation and login success are not established by this lane. No guest fixture
or proprietary library is executed here.

`migration/finalize_p0_elf_metadata_bounds.py` reads actual downloaded artifact
ZIPs, raw GitHub run/artifact metadata, sealed approved input bytes, full local
Git histories for the three changed owners and the validation host, plus both
historical ZIPs. It checks evidence before writing a fresh candidate directory
outside the builder. It cannot publish, activate, assign the review anchor,
change production pins, or grant build eligibility. Its candidate must undergo
independent review before activation.
