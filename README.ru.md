Независимая сборка с открытым исходным кодом на основе **SideStore** и **LiveContainer**, ориентированная на надёжное продление подписи (refresh) на самом устройстве, понятное расписание, проверку результатов и настройку, доступную новичкам.

<a id="current-status-v310-is-not-recommended"></a>

## Текущий статус: v3.1.0 не рекомендуется

> [!WARNING]
> **Не считайте v3.1.0 рекомендуемым стабильным релизом.** Сбои входа в Apple Account и подготовки профилей подписи (provisioning) расследуются в [Issue #42](https://github.com/NRG-Wardog/sidestore-auto-refresh/issues/42). Тестирование и исправления продолжаются. Успешный запуск CI не доказывает, что вход или обновление работают на физическом устройстве.

- **Публичный релиз:** [v3.1.0](https://github.com/NRG-Wardog/sidestore-auto-refresh/releases/tag/v3.1.0) остаётся доступным для справки, с известными проблемами. Это не тот же артефакт, что и диагностические сборки, проходящие тестирование.
- **Сборки для разработки:** кандидаты из `fix/v3.1.0-audit` предназначены для диагностики и проверки. Они не являются новым публичным релизом или подтверждённым исправлением.
- **Приостановка релизов:** нового релиза не будет, пока сопровождающий проекта не завершит полное тестирование входа и критически важных сценариев на собственном устройстве. Задачи остаются открытыми до подтверждения их приёмочных проверок; одного CI для их закрытия недостаточно.
- **Предыдущие версии:** v3.0.2, комбинированная v2 и отдельная v1 остаются историческими вариантами. Этот README не подтверждает безопасность старого релиза в качестве замены и не рекомендует откат.
- **Существующие установки:** сохраните свою конфигурацию и создайте резервные копии важных данных гостевых приложений. Не удаляйте приложение, не сбрасывайте данные учётной записи и не заменяйте записи сопряжения в попытке восстановить работу наугад.

Этот независимый проект объединяет LiveContainer и SideStore в одном интерфейсе. Для первоначальной установки и сопряжения нужен компьютер. После настройки предусмотренный маршрут обновления использует **Wi-Fi + официальный LocalDevVPN из App Store**, при этом компьютер не требуется держать подключённым. Обновление только через сотовую сеть остаётся экспериментальным.

<a id="why-this-project-exists"></a>

## Зачем существует этот проект

Я создал этот проект, потому что стандартный маршрут обновления SideStore ненадёжно работал в моей конфигурации. Ключевым исправлением стала не ещё одна команда или триггер вокруг того же процесса, а изменение транспорта на самом устройстве, через который осуществляется доступ к системным службам iPhone.

Предусмотренный в проекте маршрут на самом устройстве:

```text
official LocalDevVPN -> Lockdown -> CoreDeviceProxy TLS -> CDTunnel -> RSD -> AFC / InstallationProxy
```

Когда этот маршрут заработал, проект превратился в более цельное решение LiveContainer + SideStore: явное расписание обновлений, история и проверка результатов, диагностика по этапам, варианты отображения, элементы возврата из гостевых приложений (Guest Return) и единый интерфейс v3.

<a id="what-this-project-improves"></a>

### Что улучшает этот проект

| Область | Что предлагает этот проект |
| --- | --- |
| **Надёжный транспорт на самом устройстве** | Заменяет маршрут служб Lockdown, который не работал в моей конфигурации, на используемый в проекте путь **LocalDevVPN -> CoreDevice -> RSD** |
| **Действительно единая работа с LiveContainer + SideStore** | В v3 LiveContainer остаётся хостом, а доступ к SideStore предоставляется через ограниченный сервисный интерфейс, поэтому обычная работа проходит в **Home / Apps / Sources / Refresh / Settings** (главная / приложения / источники / обновление / настройки), без перехода в отдельный встроенный интерфейс SideStore |
| **Явная автоматизация обновлений** | Управляемые пользователем расписания **каждые шесть часов, ежедневно и еженедельно**, предпочтительное время, уведомления, учёт сроков и сохраняемая история |
| **Проверенные результаты обновлений** | Каждый запуск сопоставляется с фактическим результатом, поэтому сам по себе старт задачи, передача управления или отправка запроса не выдаются за успешное обновление |
| **Полезная диагностика** | Различает сбои VPN, CoreDevice, heartbeat, RSD, Lockdown, подписи и установки, вместо объединения несвязанных ошибок в одно общее сообщение |
| **Более удобный просмотр приложений** | Добавляет **List, Grid и Compact List** (список, сетка и компактный список), сохраняемые настройки вида и необязательные подписи в сетке; этих специфичных для проекта элементов управления видом нет в списке приложений исходного LiveContainer, проверенном для этого сравнения |
| **Более удобная навигация в гостевых приложениях** | Добавляет собственный элемент **Return** (возврат), **Start Collapsed** (запуск в свёрнутом виде), сохранение позиции и настраиваемые цвета значка/фона для полноэкранного и прямого запуска гостевых приложений |
| **Обновление без ПК после настройки** | Компьютер по-прежнему используется для первоначальной установки и сопряжения, но поддерживаемый маршрут обновления рассчитан на работу на iPhone с Wi-Fi + официальным LocalDevVPN без постоянно подключённого ПК |

## Установка

<a id="before-you-start"></a>

### Перед началом

**Инструкции ниже описывают настройку опубликованной v3; они не являются рекомендацией устанавливать v3.1.0, пока проблема входа не решена.** Прочтите раздел [Текущий статус](#current-status-v310-is-not-recommended) и [примечания к релизу](https://github.com/NRG-Wardog/sidestore-auto-refresh/releases/tag/v3.1.0), прежде чем решать, стоит ли её тестировать.

Для контролируемого тестирования публичного релиза установочным файлом является `LiveContainer-SideStore-v3.1.0.ipa`. Архивы исходного кода GitHub не являются устанавливаемыми IPA. Частные диагностические кандидаты нужно идентифицировать по точной ревизии сборщика и контрольной сумме, а не только по отображаемой версии.

Проверьте следующее перед установкой:

| Проверка | Что потребуется |
| --- | --- |
| **Устройство** | Поддерживаемый iPhone или iPad, разблокированный во время первоначальной настройки |
| **Компьютер** | Windows, macOS или Linux, только для первоначальной установки и сопряжения |
| **Установщик** | [iLoader](https://github.com/nab138/iloader/releases/latest) **2.3.1 или новее** либо другой совместимый установщик IPA |
| **Учётная запись Apple** | Apple Account / Personal Team, которая будет подписывать IPA |
| **Режим разработчика (Developer Mode)** | Включить после установки |
| **Сопряжение** | Данные сопряжения, созданные для **именно того физического устройства**, которое используется |
| **Сеть** | Wi-Fi; должны быть доступны текущие **IP Address и Subnet Mask** (IP-адрес и маска подсети) iPhone |
| **VPN** | Официальный **LocalDevVPN** из App Store от **Coxson Engineering LLC** |
| **Расширения приложения** | Сохраните необходимые расширения комбинированной сборки, включая **LiveProcess** |
| **Существующая установка** | При обновлении устанавливайте поверх соответствующей существующей сборки LiveContainer с той же идентичностью подписи; не удаляйте её предварительно в качестве обычного шага |

Если сначала хотите разобраться в отличиях, см. [Что улучшает этот проект](#what-this-project-improves). Иначе выполняйте следующие шаги по порядку.

<a id="step-1-download-the-correct-ipa"></a>

### Шаг 1: скачайте правильный IPA

Только для справки или контролируемого тестирования, опубликованный артефакт v3.1.0:

**[LiveContainer-SideStore-v3.1.0.ipa](https://github.com/NRG-Wardog/sidestore-auto-refresh/releases/download/v3.1.0/LiveContainer-SideStore-v3.1.0.ipa)**

Не используйте встроенный в iLoader установщик стандартного SideStore или стандартного LiveContainer + SideStore, если хотите модифицированную сборку этого проекта. Используйте **Import IPA** (импорт IPA) и выберите IPA, скачанный из этого репозитория.

Альтернативные линейки продукта:

- **Отдельный SideStore:** [v1.0.4](https://github.com/NRG-Wardog/sidestore-auto-refresh/releases/tag/v1.0.4)
- **Предыдущий комбинированный интерфейс:** [v2.1.1](https://github.com/NRG-Wardog/sidestore-auto-refresh/releases/tag/v2.1.1)
- **Историческая объединённая сборка:** [v3.0.2](https://github.com/NRG-Wardog/sidestore-auto-refresh/releases/tag/v3.0.2)

<a id="step-2-install-with-iloader"></a>

### Шаг 2: установите через iLoader

1. Установите/откройте [iLoader](https://github.com/nab138/iloader/releases/latest).
2. В Windows убедитесь, что установлены драйверы устройств Apple.
3. Подключите iPhone по USB, разблокируйте его и нажмите **Trust** (доверять), если появится запрос.
4. В iLoader выберите подключённое устройство.
5. Войдите в Apple Account, которую хотите использовать для подписи.
6. Откройте **Installers -> Import IPA** (установщики -> импорт IPA).
7. Выберите `LiveContainer-SideStore-v3.1.0.ipa`.
8. Сохраните необходимые расширения приложения, включая **LiveProcess**. Не удаляйте все расширения.
9. Дождитесь, пока iLoader подпишет и установит IPA. Не отключайте и не блокируйте устройство до завершения установки.

<a id="step-3-trust-the-app-and-enable-developer-mode"></a>

### Шаг 3: разрешите доверие приложению и включите режим разработчика

Если iOS показывает **Untrusted Developer** (ненадёжный разработчик):

`Settings -> General -> VPN & Device Management -> Developer App -> Trust`

Затем включите режим разработчика:

`Settings -> Privacy & Security -> Developer Mode`

Устройство может перезагрузиться. После перезагрузки подтвердите **Turn On** (включить), если появится запрос.

<a id="step-4-place-the-pairing-file"></a>

### Шаг 4: разместите файл сопряжения

Оставьте устройство подключённым по USB и разблокированным.

В iLoader:

1. Откройте **Management** (управление).
2. Откройте **Manage Pairing File** (управление файлом сопряжения).
3. Если приложение не отображается в списке, используйте **Rescan Installed Apps** (повторный поиск установленных приложений).
4. Найдите только что установленное приложение, совместимое с SideStore.
5. Нажмите **Place** (разместить) для этого приложения либо **Place In All Apps** (разместить во всех приложениях), только если именно это и требуется.
6. Прежде чем продолжать, дождитесь сообщения об успехе.

> [!CAUTION]
> Файлы сопряжения содержат конфиденциальные учётные данные устройства. Никогда не загружайте их на GitHub, в Discord, в обсуждение задачи, на общедоступный файлообменник и не показывайте на снимках экрана.

Ошибка транспорта, RSD или службы **не** означает автоматически, что файл сопряжения повреждён. Заменяйте данные сопряжения, только когда диагностика действительно указывает на сопряжение как на этап сбоя.

<a id="step-5-install-the-correct-localdevvpn"></a>

### Шаг 5: установите правильный LocalDevVPN

Установите официальный **[LocalDevVPN](https://apps.apple.com/us/app/localdevvpn/id6755608044)** из App Store и убедитесь, что разработчик — **Coxson Engineering LLC**.

Поддерживаемый маршрут CoreDevice не требует второго VPN IKEv2/IPsec.

<a id="step-6-find-the-iphones-wi-fi-subnet"></a>

### Шаг 6: определите подсеть Wi-Fi iPhone

На iPhone откройте настройки Wi-Fi и нажмите ⓘ рядом с подключённой сетью:

`Settings -> Wi-Fi -> ⓘ next to the connected network`

Запишите:

- **IP Address** (IP-адрес)
- **Subnet Mask** (маска подсети)

Пример:

```text
IP Address:  192.168.1.50
Subnet Mask: 255.255.255.0
```

В этом примере используется подсеть `192.168.1.x/24`.

> [!WARNING]
> Не копируйте адреса из примера вслепую. Используйте адреса из **вашей текущей подсети Wi-Fi**.

<a id="step-7-choose-two-unused-localdevvpn-addresses"></a>

### Шаг 7: выберите два неиспользуемых адреса LocalDevVPN

Выберите **два разных неиспользуемых IPv4-адреса в той же подсети, к которой сейчас подключён iPhone по Wi-Fi**.

Пример только для `192.168.1.x/24`:

```text
Tunnel IP: 192.168.1.240/32
Device IP: 192.168.1.241/32
```

**Не** используйте:

- фактический IP-адрес Wi-Fi iPhone
- IP-адрес маршрутизатора/шлюза по умолчанию
- IP-адрес компьютера
- IP-адрес, уже назначенный другому устройству
- IP-адрес за пределами текущей подсети Wi-Fi
Надёжнее всего проверить список аренд DHCP или подключённых клиентов на маршрутизаторе. Одно лишь отсутствие ответа на ping не доказывает, что адрес свободен.

<a id="step-8-configure-localdevvpn"></a>

### Шаг 8: настройте LocalDevVPN

Откройте настройки сети:

`LocalDevVPN -> Settings -> Network Configuration`

Затем:

1. Введите выбранный **Tunnel IP** (IP туннеля) с `/32`.
2. Введите выбранный **Device IP** (IP устройства) с `/32`.
3. Включите **Allow Intermediate Addresses** (разрешить промежуточные адреса).
4. Нажмите **Done** (готово).
5. Нажмите **Save & Apply** (сохранить и применить).
6. Подключите LocalDevVPN.
7. Откройте **Session Details** (сведения о сеансе) и убедитесь, что заданные значения сохранились.

> [!IMPORTANT]
> Если вы переходите в сеть Wi-Fi с другой подсетью, обновите Tunnel IP и Device IP для этой сети перед следующим обновлением.

<a id="step-9-open-v3-and-complete-account--signing"></a>

### Шаг 9: откройте v3 и завершите настройку учётной записи и подписи

**Известная блокирующая проблема:** вход или provisioning в v3.1.0 могут завершаться сбоем. См. [Issue #42](https://github.com/NRG-Wardog/sidestore-auto-refresh/issues/42). Не рассчитывайте, что описанный ниже процесс обязательно завершится, и не стирайте данные, пытаясь заставить его работать.

Откройте установленное приложение. Обычная работа с v3 происходит в **Home / Apps / Sources / Refresh / Settings** (главная / приложения / источники / обновление / настройки).

Перейдите к учётной записи и подписи, затем к входу/аутентификации:

`Settings -> Account and Signing -> Sign In / Authenticate`

Завершите действия с учётной записью при подключённых Wi-Fi и LocalDevVPN.

<a id="step-10-run-one-manual-refresh-before-enabling-automation"></a>

### Шаг 10: выполните одно ручное обновление перед включением автоматизации

Откройте **Refresh** (обновление) и сначала выполните ручное обновление.

Прежде чем продолжать, убедитесь, что:

- LocalDevVPN подключён
- транспорт отмечен как доступный/готовый
- обновление доходит до конвейера подписи/установки
- итоговый результат записан как успешный в истории обновлений/проверке результатов

Самого запуска задачи или передачи управления недостаточно. Подтвердите итоговый результат обновления.

Если произошёл сбой, прежде чем что-либо менять, прочтите указанный этап. Диагностика предназначена для различения сбоев VPN, CoreDevice, heartbeat, RSD, Lockdown, подписи, установки и сопряжения.

<a id="step-11-enable-automatic-refresh"></a>

### Шаг 11: включите автоматическое обновление

Только после успешного ручного обновления:

1. Откройте вкладку/настройки **Refresh** (обновление).
2. Включите автоматическое обновление.
3. Выберите **Every Six Hours** (каждые шесть часов), **Daily** (ежедневно) или **Weekly** (еженедельно), если эти варианты доступны.
4. Установите предпочтительное время/день.
5. Предпочтите время, когда iPhone обычно подключён к той сети Wi-Fi, для которой настроен LocalDevVPN.
6. Разрешите уведомления, если хотите получать оповещения о начале, сбоях и приближающихся сроках.

> [!NOTE]
> iOS выполняет фоновые задачи по возможности. Выбранное время не является точным будильником, и iOS может запустить задачу позже. Проверьте последнее подтверждённое обновление до того, как срок действия подписи приблизится к окончанию.

<a id="step-12-confirm-pc-free-runtime"></a>

### Шаг 12: проверьте работу без ПК

После первоначальной установки и настройки сопряжения поддерживаемое обновление рассчитано на использование:

```text
iPhone/iPad + Wi-Fi + official LocalDevVPN
```

Для обычного обновления компьютер и USB-кабель не должны оставаться подключёнными.

<a id="updating-without-losing-your-setup"></a>

### Обновление без потери конфигурации

Для комбинированных сборок v3/v2 устанавливайте новый соответствующий IPA **поверх существующей установки LiveContainer**, используя ту же Apple Account / Personal Team и совпадающие идентификаторы.

**Не** удаляйте приложение перед обновлением в качестве обычного шага. Перед обновлением создайте резервные копии важных данных гостевых приложений.

Для отдельного SideStore устанавливайте новую отдельную сборку поверх соответствующей существующей установки SideStore. Не устанавливайте отдельный IPA SideStore поверх LiveContainer.

<a id="if-something-does-not-work"></a>

### Если что-то не работает

Сначала проверьте следующее по порядку:

1. Точный релиз/сборку и имя файла IPA.
2. Режим разработчика (Developer Mode) и статус доверия.
3. Данные сопряжения относятся именно к этому устройству.
4. LocalDevVPN является официальной сборкой из App Store и подключён.
5. Tunnel IP и Device IP — **неиспользуемые адреса в той же подсети Wi-Fi**, а не IP-адреса iPhone, маршрутизатора или компьютера.
6. **Allow Intermediate Addresses** включено и была нажата кнопка **Save & Apply**.
7. Аутентификация учётной записи/подписи завершена.
8. Прочтите точный этап диагностированного сбоя перед сбросом данных сопряжения/учётной записи.
9. Если сеть Wi-Fi изменилась, перенастройте LocalDevVPN для новой подсети.
10. Если автоматическое обновление не запустилось, сначала проверьте ручное; iOS не гарантирует точное время фонового выполнения.

Для более подробного поиска неисправностей см. [Устранение неполадок](#troubleshooting) и [Проверка](docs/VERIFICATION.md).

<a id="what-is-this"></a>

## Что это такое?

**v3 объединяет Home, Apps, Sources, Refresh и Settings в единый интерфейс приложения.** Для обычных операций больше не нужно переключаться между LiveContainer и старым встроенным интерфейсом SideStore. LocalDevVPN остаётся отдельным приложением, используемым транспортом обновления.


Этот проект представляет собой модифицированную сборку SideStore / LiveContainer, с которой обновлением на самом устройстве проще управлять и легче проверять его результат.

Она добавляет:

- ручное обновление прямо на iPhone
- расписания обновления каждые шесть часов, ежедневно и еженедельно
- настройку предпочтительного времени обновления
- сохраняемую историю обновлений
- ограниченную логику повторных попыток и восстановления
- явную проверку результата обновления
- транспортный маршрут **LocalDevVPN + CoreDevice** на самом устройстве
- комбинированную сборку LiveContainer с уже встроенным модифицированным SideStore
- элементы возврата из гостевых приложений (Return) в комбинированной сборке
- **Start Collapsed** (запуск в свёрнутом виде) и **настраиваемые цвета кнопки Return** в комбинированной v2.1.0

Цель проста: после первоначальной установки и настройки сопряжения обычное обновление должно выполняться на iPhone без постоянно подключённого ПК.

## Что нового в v3.0.1?

v3.0.1 была предыдущим обслуживающим релизом объединённой линейки LiveContainer + SideStore v3. Она сохраняет рабочую архитектуру v3 и сосредоточена на том, чтобы SideStore оставался деталью реализации бэкенда, а за видимый интерфейс отвечал LiveContainer.

- **Бэкенд SideStore без интерфейса:** обычные сценарии v3 больше не зависят от показа удалённого интерфейса SideStore. LiveContainer отвечает за пользовательскую навигацию, формы, панели, предупреждения, подтверждения, прогресс и отображение ошибок.
- **Пошаговый вход и 2FA:** аутентификация учётной записи управляется из единого интерфейса с более понятным двухэтапным процессом 2FA: выбор доставки на доверенное устройство или телефон, затем ввод кода.
- **Экраны управления под контролем хоста:** сертификаты, данные разработчика, сопряжение, источники, настройки, диагностика и связанные сценарии используют модель сервисных/DTO-команд v3, вместо прямого показа экранов SideStore.
- **Главная страница Home позволяет действовать:** основные строки статуса теперь ведут прямо в соответствующие разделы Apps (приложения), Sign In (вход), Developer Services (службы разработчика), Certificates (сертификаты), Pairing (сопряжение) или Refresh (обновление).
- **Упорядоченные Settings (настройки):** разделы расположены по значимости, Guest Runtime (среда выполнения гостевых приложений) находится в конце, а информация Build Candidate (кандидат сборки) перенесена вниз.
- **Меньше тупиковых переходов:** разделы, требующие учётную запись, направляют к Sign In (вход), если учётная запись недоступна.
- **Исправление выбора телефона для 2FA:** выбор номера телефона запрашивает доставку на этот номер, а не отменяет процесс.
- **Стабильность релиза и работы:** релиз сохраняет текущее поведение обновления, транспорта, подписи, хранения данных, среды выполнения гостевых приложений и LiveProcess, не вводя несвязанный рефакторинг.

Опубликованный IPA v3.0.1 собран из той же протестированной реализации v3; изменения релиза/версии и подтверждающих материалов были применены после этого. Пользователям существующей v3 следует устанавливать его поверх соответствующей установки LiveContainer с той же идентичностью подписи, а не удалять приложение заранее.

SideStore по-прежнему отвечает за свою базу данных, Keychain, логику аутентификации, подпись, provisioning, источники и установку. LiveContainer по-прежнему отвечает за гостевые приложения и их выполнение. Сервисный мост v3 связывает эти компоненты без дублирования сохраняемого состояния.

Для поддерживаемого маршрута обновления по-прежнему требуются Wi-Fi и официальное приложение LocalDevVPN. iOS управляет временем фонового выполнения; расписание не является точным будильником. Issue #18 по-прежнему отслеживается отдельно, потому что результат аутентификации Apple для одного затронутого пользователя невозможно доказать универсально с помощью CI или одного устройства.

## Что нового в v1.0.4 и v2.1.1?

Issue 17 добавляет сохраняемые варианты отображения приложений в разделе **Interface** (интерфейс):

## Что нового в отдельной v1.0.3?

<a id="how-this-project-differs-from-the-original-projects"></a>

## Чем этот проект отличается от исходных проектов

SideStore и LiveContainer — исходная основа; этот репозиторий превращает их в другое целостное решение для данного сценария использования. Основные преимущества: **маршрут обновления CoreDevice/RSD**, **единый процесс работы LiveContainer + SideStore в v3**, явное расписание и история, проверка каждого запуска, структурированная диагностика и дополнительные элементы управления интерфейсом приложений/гостей, описанные выше.

Чтобы увидеть точные отличия на уровне исходного кода, раскройте **Техническое сравнение с исходными проектами** в начале этого README.

<a id="what-this-project-does-not-change"></a>

### Чего этот проект не меняет

- Он **не** отменяет обычный срок действия подписи Personal Team. Он обновляет её до истечения срока.
- Он **не** гарантирует точное время фонового выполнения. Планированием задач управляет iOS.
- Он пока **не** делает обновление только через сотовую сеть стабильной функцией.
- Он **не** требует джейлбрейка для поддерживаемого маршрута через Wi-Fi.
- Он **не** делает гостевые приложения LiveContainer эквивалентными отдельно установленным приложениям iOS.
- Он **не** гарантирует, что iOS сохранит работающим каждый гостевой процесс.

Поскольку комбинированная сборка модифицирует LiveContainer и содержит встроенный код SideStore, применяйте к ней ту же модель доверия, что и к любой модифицированной сборке LiveContainer. Этот репозиторий имеет открытый исходный код, и вы можете [собрать его самостоятельно](#build-it-yourself), если предпочитаете лично проверить процесс сборки.

## Обычное повседневное использование

Когда настройка работает:

- обеспечивайте доступность Wi-Fi
- по возможности держите LocalDevVPN правильно настроенным и подключённым
- оставьте включённым Background App Refresh (фоновое обновление приложений)
- время от времени проверяйте историю обновлений на успешные запуски

После первоначальной настройки компьютер обычно не должен требоваться во время обновления.

Обновление только через сотовую сеть остаётся экспериментальным.

<a id="troubleshooting"></a>

## Устранение неполадок

| Проблема | Что проверить сначала |
| --- | --- |
| iLoader не видит iPhone в Windows | Убедитесь, что установлены драйверы устройств Apple, переподключите USB, разблокируйте телефон и нажмите **Trust** (доверять) |
| iLoader сообщает, что устройство не выбрано | Выберите iPhone в iLoader перед выполнением **Import IPA** (импорт IPA) или действий с сопряжением |
| Приложение показывает Untrusted Developer (ненадёжный разработчик) | `Settings -> General -> VPN & Device Management -> Developer App -> Trust` |
| Приложение не открывается | Убедитесь, что Developer Mode (режим разработчика) включён в `Settings -> Privacy & Security` |
| Подтверждено отсутствие/недействительность сопряжения | Переподключите USB, откройте **Manage Pairing File**, используйте **Rescan Installed Apps**, затем снова **Place** для именно этого устройства |
| В v3.1.0 не удаётся вход или provisioning | Следите за [Issue #42](https://github.com/NRG-Wardog/sidestore-auto-refresh/issues/42). Запишите точную сборку и ошибку с удалёнными конфиденциальными данными; не удаляйте приложение и не сбрасывайте данные учётной записи/сопряжения в попытке исправить проблему наугад |
| Ошибка запуска службы или транспорта в v3 | Прочтите этап и код ошибки в диагностике. Не сбрасывайте данные учётной записи или сопряжения лишь потому, что не удалось подключиться к службе или сети |
| LocalDevVPN не подключается | Перепроверьте Network Configuration (конфигурацию сети), обе конечные точки `/32` и **Allow Intermediate Addresses** |
| LocalDevVPN подключается, но обновление не удаётся | Убедитесь, что адреса находятся в текущей подсети Wi-Fi iPhone и ещё не используются |
| Обновление перестало работать после смены Wi-Fi | Перенастройте Tunnel IP и Device IP для новой подсети |
| Ручное обновление не удаётся | Проверьте Wi-Fi, LocalDevVPN, сопряжение, вход в SideStore и записанный результат/историю обновления |
| Обновление по расписанию было пропущено | Убедитесь, что ручное обновление работает и Background App Refresh включён. Выбранное время не является точным временем пробуждения |
| Недостаточно App ID | У бесплатных Apple Account есть ограничения на регистрацию. Не удаляйте/переустанавливайте сборки многократно. Дождитесь истечения регистраций или повторно используйте совпадающие идентификаторы, если это поддерживается |
| Предупреждение о подписи гостевого приложения | Это предупреждение не связано с подтверждённым статусом обновления. Откройте указанное гостевое приложение и сообщите, запускается ли оно в действительности |
| Обновление только через сотовую сеть не удаётся | Транспорт только через сотовую сеть является экспериментальным и не входит в поддерживаемый маршрут через Wi-Fi |

Для более подробного исследования см. [Проверка](docs/VERIFICATION.md), [Совместимость](docs/COMPATIBILITY.md) и [Issue #1](https://github.com/NRG-Wardog/sidestore-auto-refresh/issues/1).

<a id="guest-return-behavior"></a>

## Поведение возврата из гостевых приложений

| Режим выполнения | Поведение Return |
| --- | --- |
| Оконная многозадачность LiveProcess | Плавающая кнопка Return скрыта. Используйте обычные элементы управления окном. |
| Полноэкранный или развёрнутый LiveProcess | Return активирует хост или сворачивает гостевое приложение с возвратом к хосту, не завершая намеренно гостевое приложение. |
| Повторное открытие сохранённого гостевого приложения | Если существующий экземпляр всё ещё работает, он используется повторно. Устаревшие экземпляры очищаются перед холодным запуском. |
| Прямой запуск гостевого приложения в процессе хоста | Использует существующий маршрут возврата через перезапуск. Память гостевого приложения не сохраняется. |

Нажмите и удерживайте кнопку Return, чтобы свернуть её в боковую вкладку. Коснитесь вкладки, чтобы восстановить кнопку. Её положение сохраняется и ограничивается допустимыми границами после изменения размера.

v2.1.0 добавляет следующие параметры в **LiveContainer Settings > Guest Controls** (настройки LiveContainer > управление гостевыми приложениями):

- **Start Collapsed** (запуск в свёрнутом виде): новые гостевые приложения открываются с боковой вкладкой. Коснитесь её один раз, чтобы развернуть, затем нажмите Return для возврата. Использование Return снова сворачивает элемент управления, в том числе при повторном открытии сохранённого гостевого приложения. По умолчанию параметр выключен.
- **Use Custom Colors** (использовать свои цвета): выберите **Icon Color** (цвет значка) и **Button Background** (фон кнопки). Цвет значка также применяется к свёрнутой вкладке; фон вкладки остаётся прозрачным. Выключите параметр, чтобы вернуть системные цвета. Выбранные цвета сохраняются для дальнейшего использования.

Эти настройки применяются и к полноэкранному LiveProcess, и к гостевым приложениям, выполняемым непосредственно в процессе хоста. **Show Return Button** (показывать кнопку возврата) по-прежнему управляет видимостью, а оконная многозадачность по-прежнему использует обычные элементы управления окном.

<a id="technical-architecture"></a>

## Техническая архитектура

Точное описание реализации v3 и границ ответственности см. в [архитектуре на теге v3.0.2](https://github.com/NRG-Wardog/sidestore-auto-refresh/blob/v3.0.2/docs/V3_UNIFIED_ARCHITECTURE.md). Общий транспорт обновления ниже остаётся отделённым от единого интерфейса и жизненного цикла сервисов.

```text
LiveContainer triggers / embedded SideStore
    -> refresh coordination and eligibility
    -> Wi-Fi / LocalDevVPN preflight
    -> signing and refresh pipeline
    -> Lockdown -> CoreDeviceProxy TLS -> CDTunnel
    -> userspace adapter -> RSD
    -> AFC staging / InstallationProxy and profile operations
    -> correlated verification results and history
```

Маршрут CoreDevice сохраняет TLS служб, непрерывные записи CDTunnel, heartbeat во время транспортных операций, исправления размера пакетов и управления потоком, а также исправленное владение объектами FFI. Экспериментальная работа с сотовой сетью не входит в поддерживаемый маршрут через Wi-Fi.

<a id="app-layout-architecture-issue-17"></a>

### Архитектура отображения приложений App Layout (Issue #17)

Issue #17 намеренно является **функцией уровня представления**. Она не должна менять транспорт обновления, подпись, аутентификацию, фоновое планирование, согласование базы данных или конвейер CoreDevice.

```text
Interface settings
    -> persisted AppLayoutPreferences
        -> App Layout: list | grid | compactList
        -> Show app labels: true | false
    -> Apps screen presentation switch
        -> List renderer
        -> Grid renderer
        -> Compact List renderer
    -> shared app model + shared actions
        -> open / refresh / activate / deactivate / context menu
```

Требования к реализации:

- Добавить небольшую сохраняемую модель вида, например `AppLayoutStyle: String`, с вариантами `list`, `grid` и `compactList`.
- Сохранить **List** (список) по умолчанию, чтобы существующие установки сохранили текущее поведение.
- Сохранить ключи комбинированной сборки `LCAppLayoutStyle` и `LCShowAppLabels` в существующих общих настройках. Отдельная сборка использует собственные существующие имена настроек. Не добавлять новую базу данных для настроек интерфейса.
- Расширить существующий параметр **Interface -> App Layout** (интерфейс -> вид приложений), вместо создания второго элемента управления видом. Показывать **Show app labels** (показывать названия приложений) только при выбранном Grid.
- Сохранить текущий механизм отображения списка/карточек для List. Не переписывать работающее поведение списка только ради общего кода.
- Реализовать Grid как адаптивную сетку с акцентом на значках и необязательным названием приложения под каждым значком.
- Реализовать Compact List с теми же данными и действиями приложений, что и List, но с уменьшенными значками, высотой строк и вертикальными отступами.
- Направлять все три механизма отображения через одну и ту же существующую модель приложений и обработчики действий. Представления отдельных видов не должны дублировать бизнес-логику подписи, обновления, активации, установки или контекстного меню.
- Скрытие подписей Grid должно быть только визуальным. Название приложения должно оставаться доступным в качестве метки специальных возможностей.
- Рассматривать [SideloadLabs/AppNest](https://github.com/SideloadLabs/AppNest) только как визуальный ориентир. Не включать и не копировать его реализацию без отдельной проверки кода и лицензии.

<a id="patch-strategy"></a>

#### Стратегия патча

Этот репозиторий должен реализовывать функцию как детерминированный патч на этапе сборки, в соответствии с остальным проектом. Ожидается отдельный семантический патч, например `scripts/patch_app_layout.py`, который применяется к закреплённым исходникам SideStore, а не включение целых файлов исходного проекта в репозиторий.

Отдельная и комбинированная сборки сейчас используют разные ветви исходного кода SideStore. Требования к интерфейсу должны оставаться одинаковыми, но там, где структура представлений отличается, можно применять специфичные для исходников точки привязки/адаптеры. Не обновляйте встроенный в LiveContainer SideStore до официального SideStore 0.7 только ради этой функции интерфейса.

Патч должен быть идемпотентным и безопасно прекращать применение, если точки привязки в исходниках сместились. Он должен затрагивать лишь минимально необходимые для функции настройки и представление экрана Apps.

<a id="verification-gates"></a>

#### Обязательные проверки

Прежде чем считать Issue #17 завершённой:

1. Тесты репозитория доказывают идемпотентность патча и отклонение изменённых/неоднозначных точек привязки в исходниках.
2. Сгенерированный Swift успешно проходит синтаксический разбор, и сборка завершается для каждой поддерживаемой цели, получающей эту функцию.
3. List, Grid, Grid без визуальных подписей и Compact List доступны из настроек.
4. Настройки вида и подписей сохраняются после повторного запуска.
5. Открытие, обновление, активация/деактивация, отображение статуса и действия контекстного меню по-прежнему используют одни и те же базовые обработчики во всех видах.
6. Специальные возможности по-прежнему предоставляют название приложения, когда подписи Grid скрыты.
7. Эта функция не меняет исходники транспорта, подписи, аутентификации, планировщика или CoreDevice.
8. До релиза снимки экрана с устройства/приёмочные проверки охватывают все три вида.

Такое разделение сохраняет низкий риск Issue #17: меняется механизм отображения, а жизненный цикл приложения и стек обновления остаются прежними.

## Самостоятельная сборка

Этот репозиторий содержит патчи, применяемые на этапе сборки, а не постоянные включённые копии LiveContainer и SideStore. Рабочие процессы загружают закреплённые ревизии исходных проектов.

1. Создайте форк репозитория и включите GitHub Actions.
2. Запустите **LiveContainer embedded SideStore build** для комбинированного IPA или **Build Current SideStore** для отдельного.
3. Чтобы воспроизвести опубликованный пакет, переключитесь на его точный тег релиза и изучите записанную ревизию сборщика. Для v3.1.0 используйте [тег `v3.1.0`](https://github.com/NRG-Wardog/sidestore-auto-refresh/tree/v3.1.0) и сведения о происхождении в [примечаниях к релизу](https://github.com/NRG-Wardog/sidestore-auto-refresh/releases/tag/v3.1.0). Документация в `main` не означает, что соответствующие исходники v3 были влиты в эту ветку. Ветка `fix/v3.1.0-audit` содержит текущую диагностическую работу, а не публичный стабильный релиз.
4. Скачайте артефакт успешного запуска.
5. Перед установкой подпишите полученный IPA собственной Apple Account / Personal Team.

[Рабочий процесс комбинированной сборки](.github/workflows/livecontainer-build.yml) | [Рабочий процесс отдельной сборки](.github/workflows/build-current.yml)
